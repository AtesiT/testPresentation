# Презентация решения: PINN-суррогат EOS алюминия

**Файл:** `PINN_EOS_Al.pptx` — 20 слайдов, формат 16:9 (13.33 × 7.5″).
У каждого слайда есть **заметки докладчика** (в PowerPoint: «Вид → Страницы заметок» или панель «Заметки»). Там же — подсказки, что говорить.

## Как пересобрать

```bash
python3 presentation/build_deck.py        # собирает .pptx из work/*.json и work/fig/*.png
python3 presentation/proof_render.py presentation/PINN_EOS_Al.pptx   # PNG-превью в presentation/proof
```

Вся графика генерируется скриптами из `work/`: `figs_data2.py` (EDA), `figs_models.py` (метрики, карты, c_s),
`figs_extra.py` (зоны, физический лосс по зонам), `figs_stages.py` (кривые обучения), `figs_scheme.py` (схемы).
Метрики считает `work/final_eval.py` → `work/final_metrics.json`.

## Ключевые цифры (для ответов на вопросы)

- Данные: 1 130 053 строки, 20 файлов, ρ ∈ [10⁻³; 10⁴] г/см³, T ∈ [0.1; 10⁷] К.
- Тест: 20 % стратифицированной выборки, 226 011 точек.
- Vanilla MLP: R²(P) = 0.99915, медиана |ΔP| = 5.69 %, нарушений 31.87 %.
- PINN: R²(P) = 0.99865, медиана |ΔP| = 8.94 %, нарушений 0.43 % (**в 74 раза меньше**).
- Размер: 0.100 МБ (лимит 10 МБ), 25 282 параметра; 0.95 мкс на запрос, 10⁵ запросов за 0.13 с.
- Скорость звука: R² = 0.90 по log₁₀ c_s, медианное отклонение 11.7 %, точек с c_s ≥ c нет.
- Сжатие: TorchScript 28 мкс на batch=1 против 46 мкс; int8 — 0.031 МБ.

## Честные ограничения (лучше сказать самому, чем услышать вопрос)

1. Точность упирается в разрывы исходной таблицы: на стыках регионов ошибка в 1.7 раза выше.
2. Физика контролируется по точечным производным, интегральные тождества (например, согласованность по циклам) не проверяются.
3. Обучение на CPU, ~4 минуты; качество соответствует 25 тыс. параметров — большая модель дала бы лучше.
4. Baseline формально «идеален» по MSE, потому что тест содержит узлы сетки: корректнее сравнивать на прореженных таблицах (см. слайд 7).
